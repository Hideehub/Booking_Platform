# Booking platform

[![CI](https://github.com/Hideehub/Booking_Platform/actions/workflows/ci.yml/badge.svg)](https://github.com/Hideehub/Booking_Platform/actions/workflows/ci.yml)

Appointment booking for clinics, salons and consultants: customers pick a service, staff member and time, hold the slot, and pay a deposit through Paystack. Business owners manage their services, staff, hours and bookings in their own dashboard.

## Live demo

- **Site:** `<your-render-url>`
- **Customer booking page (demo business Raya.Effect):** `<your-render-url>/b/raya-effect/`
- **Owner dashboard:** `<your-render-url>/owner/` (username `demo-owner`, password `<demo password>`)

The demo runs on free hosting, so the first visit after a quiet spell takes about a minute while the server wakes up. Payments use Paystack's test mode, and emails are written to the server logs rather than sent.

## Running locally

**Requires:** Docker Desktop (or another Docker engine with Compose v2).

```bash
docker compose up
```

The first run builds the image. This starts six services:

| Service  | What it does                                                          |
|----------|-----------------------------------------------------------------------|
| `web`    | Django dev server on http://localhost:8000 (runs migrations on start) |
| `worker` | Celery worker: sends emails, runs scheduled jobs                      |
| `beat`   | Celery scheduler: hold expiry every minute, reminders every 5 minutes |
| `css`    | Tailwind, rebuilding `static/css/app.css` when templates change       |
| `db`     | Postgres 16                                                           |
| `redis`  | Redis 7 (Celery broker)                                               |

Check it's up: http://localhost:8000/healthz/ returns `{"status": "ok"}`.

In a second terminal, create an admin user and the Raya.Effect demo business (on an empty database):

```bash
docker compose exec web python manage.py createsuperuser
docker compose exec -e DEMO_OWNER_PASSWORD=choose-a-password web python manage.py seed_demo
```

| URL                                          | Page                                                  |
|----------------------------------------------|-------------------------------------------------------|
| `http://localhost:8000/`                     | Home page                                             |
| `http://localhost:8000/b/raya-effect/`       | Customer booking page for the demo business           |
| `http://localhost:8000/owner/`               | Owner dashboard (`demo-owner` / the password above)   |
| `http://localhost:8000/admin/`               | Django admin (the superuser)                          |

**Configuration:** no `.env` file is needed for local development. Dev settings supply safe defaults, including a fake Paystack key and a console email backend (emails print in the `worker` logs). To override something, copy `.env.example` to `.env` and edit it.

**Checks:**

```bash
docker compose run --rm web pytest
docker compose run --rm web ruff check .
docker compose run --rm web mypy .
```

**Stop:** `Ctrl+C`, then `docker compose down`. Add `-v` to also delete the database.

For a step-by-step walkthrough of booking, payment, emails and hold expiry, see [docs/manual-testing.md](docs/manual-testing.md).

## Deploying (free tier)

The app runs as **one free Render web service**: gunicorn and the Celery worker (with beat embedded) share the container ([`bin/start.sh`](bin/start.sh)). Postgres is on **Neon** and Redis on **Upstash**, both on free plans. Why this shape, and the measured usage behind it: [docs/decisions.md](docs/decisions.md), decision 17.

1. **Neon (Postgres):** create a project and copy the **direct** connection string, not the `-pooler` one. Keep `?sslmode=require` on the end.
2. **Upstash (Redis):** create a Redis database and copy its TLS URL: `rediss://default:<password>@<host>:6379`.
3. **Render:** New → **Blueprint** → connect this repository. Render reads [`render.yaml`](render.yaml) and asks for the secret values:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Neon direct connection string |
   | `REDIS_URL` | Upstash `rediss://` URL |
   | `PAYSTACK_SECRET_KEY` | your Paystack **test** secret key (`sk_test_…`) |
   | `DEMO_OWNER_PASSWORD` | password for the `demo-owner` dashboard login (8+ characters) |
   | `DJANGO_SUPERUSER_USERNAME` / `_EMAIL` / `_PASSWORD` | your admin login |

   `SECRET_KEY` is generated by Render. The site's URL and allowed hosts come from Render automatically, so don't set `SITE_URL`.
4. **Deploy.** The service is named `booking-platform`, so its URL is `https://booking-platform.onrender.com` (Render adds a suffix if that name is taken). On start, the container runs migrations, creates the superuser if it doesn't exist, and seeds the Raya.Effect demo business. Each step does nothing once it has been done, and **existing passwords are never changed**; to change one later, use the admin. Check `<your-render-url>/healthz/` returns `{"status": "ok"}`.
5. **Paystack:** in the dashboard (Settings → API Keys & Webhooks), set the **test** webhook URL to `<your-render-url>/payments/paystack/webhook/`.

**Free-tier notes:**

- The service sleeps after about 15 minutes without visitors and takes about a minute to wake. Scheduled jobs run every 15 minutes while it's awake and catch up as soon as it wakes.
- **Don't point an uptime monitor at the live site.** Keeping it awake around the clock is what would push Redis and Neon toward their free limits.
- Emails go to the service logs (`EMAIL_URL=consolemail://`). To send real email, set `EMAIL_URL` to an SMTP provider's URL, for example `smtp+tls://user:password@smtp.example.com:587`, and use a `DEFAULT_FROM_EMAIL` on that provider's verified domain.
